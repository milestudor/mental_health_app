# Current integration architecture

Vue owns exercise state, phase/count timing, grounding Next/Skip, Pause/Resume/Stop, independent support, reduced motion and stale-request guards. FastAPI owns validation, context assembly, model adapters and transactional SQLite writes. FastAPI serves the production Vue build and JSON endpoints on localhost.

`Session.skill_id` accepts only `breathing-v1` or `grounding-v1`; missing values retain the breathing default for old callers. Each browser session gets an idempotent UUID. SQLite `BEGIN IMMEDIATE`, profile ownership checks and terminal-status guards protect persisted identity and completion from stale state changes. The frontend serializes ordinary checkpoints. A localStorage checkpoint supports recording an interruption after refresh. This is not synchronization across tabs.

Breathing uses a monotonic animation-frame clock: six four-second inhales and six six-second exhales. Hidden tabs or callback gaps over 1.5 seconds pause rather than skip unseen time. Grounding accumulates active time but has no duration limit and only explicit Next/Skip advances it. Opening support pauses either exercise. Skip and Next have identical advancement semantics; no answers or individual skipped-sense flags are recorded. Completion does not prove any prompt was followed.

Profiles persist explicit names/goals/display/motion/no-typing settings. The latest check-in category and aggregate status counts can be included in context. Current-view override is separate from saved default. History and response snapshots are profile-scoped; older transcripts are excluded from model personalization, while up to 12 current-conversation messages support follow-ups. All data must be fictional.

Default mock mode maps explicit intents to reviewed text. The optional live adapter uses the inherited Chat Completions Structured Outputs request and validates a one-field reply, 350 words/4000 characters maximum (previously 90/600). Schema validation does not establish semantic safety. Reviewed feature facts constrain app claims; the current live prompt permits general model knowledge for other questions and does not provide browsing tools. Saved profile/activity context is optional and defaults off in the browser. Mocked-mode assertions are omitted from live app facts. Provider failure, timeout or invalid output produces a fixed fallback. Pending and terminal outcomes are persisted. Vue renders text without HTML interpretation.

A per-process counter increments before each provider attempt. The 51st would-be attempt selects mocked catalog text instead. One worker/process and host session accounting are required; restart-resistant budgets and multi-instance coordination are outside scope. Browser chat status reports mock mode after the cap when refreshed; individual message outcomes are always labeled.

Tests: pytest API/SQLite fixtures and replaced provider transports for deterministic checks; Playwright for actual browser controls, foreground timing, narrow layout and request interception. Network failures in browser evidence are intercepted requests, not a claim of an actual provider outage. No clinical or participant study is performed.

Later live evidence: the student-run six-attempt selection records `gpt-6.1-sol` live outcomes for all six replies. [The assisted review](../evidence/live-review.md) compares these three independent pairs without changing the app code. They supplement, rather than replace, mocked tests. Wider semantic adherence, nonzero-history live interpretation and long follow-ups remain unverified.

Current live-chat scope is documented in [general-chat.md](general-chat.md). The new 70-test mocked suite and two-call real UI check are separate from the previous six-case review. Browser sharing defaults off; API compatibility defaults on unless explicitly opted out. Provider request bodies use `max_completion_tokens: 4096`, low reasoning effort for GPT-5/6, and bounded timeouts. These limits do not establish semantic safety or arbitrary-topic accuracy.

Finalization added a targeted instruction to include Pause/Stop when answering exercise-step or skipping questions, after both first-pass grounding answers omitted that reminder. [Final live evidence](../evidence/final-live-review.md) preserves the omission and repeat. No exercise timing/control change was made.
